## 每日一问：28 天里你最大的一个认知改变是什么？

**从「让 AI 给我一个能跑的成品」，变成「我把需求说清楚、把验收标准定死，AI 才能一次做对」。**

前两周我总想着"快点看到东西"，需求丢得含糊，结果来回改。后来我学会把一件事拆成**可观察的**目标——改哪个文件、怎么算通过、失败什么样——一次性说清，AI 反而做得又快又对。28 天里真正省下来的时间，全来自这一步。

## 结营总结（200 字以内）

28 天，我把「热浪 TREND WAVE」从零做到了公网可用的 v1.0：4 平台真实热搜聚合、三视图、收藏闭环、错误处理、发布前检查 Skill、发布与回滚演练。最大的收获不是学会了调 API，而是认清了「能跑 ≠ 能交付」——一个作品要能被复验、能回退、能解释，才算数。Day 20 的 API Key 泄露教会我密钥不进 git；Day 24 的累积 Bug 教会我先定位再动手；Day 27 真人一句「还有打卡痕迹」，教会我站在用户那边看。工具会越来越强，但「说清需求、定死标准、自己动手验一遍」这三件事，得我自己扛。
